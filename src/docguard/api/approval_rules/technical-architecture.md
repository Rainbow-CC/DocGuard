# 技术架构报告审核

> 这是一个用于展示和维护审批规则的示例文件，不会改变实际审核任务的规则包或 Finding 契约。

## 适用范围

适用于提交审批的技术架构、概要设计和部署设计类文档。审批人应结合项目立项范围、适用制度和当前版本的审核要求作出判断。

## 审批前置条件

- 文档版本、编制人、复核人和提交日期完整可追溯。
- 架构图、部署图和资源配置表已经随文档提交。
- 关键容量、可用性和安全边界有明确的说明或引用材料。

## 审批要点

### R-EXAMPLE-001：架构范围完整性

系统边界、外部依赖、主要组件及其职责应明确。缺少关键组件时，应退回补充，而不是依据经验推定其实现方式。

### R-EXAMPLE-002：部署与高可用说明

关键服务的实例数、故障切换方式和数据一致性策略应与部署图、资源表保持一致；如证据不足，应记录为待补充材料。

### R-EXAMPLE-003：容量依据

并发量、处理量和存储量应说明数据来源、统计周期、峰值口径及增长假设，确保审批结论可复核。

### R-004: 用户估算

参照《》进行用户估算。

## 审批结论与留痕

审批意见应引用对应章节或附件，并明确结论为“通过”“有条件通过”或“退回补充”。有条件通过时，应记录责任人、完成期限和复核方式。

## 维护说明

新增一种审批规则时，在本目录增加一个以英文短横线标识命名的 Markdown 文件，例如 `overview-design.md`。文件首部可选 `title`、`description` 和 `order`，其余内容使用普通 Markdown 标题即可自动生成左侧大纲。
