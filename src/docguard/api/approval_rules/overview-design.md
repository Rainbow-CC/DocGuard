# 概要设计审核

> 这是一个用于展示和维护概要设计审批规则的示例文件，不会改变实际审核任务的规则包或 Finding 契约。

## 适用范围

适用于系统概要设计、方案设计和主要模块设计文档的审批。详细设计、接口定义及部署实施细节可在后续阶段另行复核。

## 审批前置条件

- 文档已标注版本、编制人、复核人和提交日期。
- 业务目标、建设范围和涉及系统已经明确。
- 关键流程、模块边界和外部依赖已提供对应图表或说明。

## 审批要点

### R-OVERVIEW-EXAMPLE-001：业务范围与系统边界

概要设计应明确本次建设覆盖的业务范围、系统边界及不在本期范围内的事项。系统间职责不清时，应退回补充边界说明。

### R-OVERVIEW-EXAMPLE-002：模块职责与接口关系

每个主要模块应说明职责、输入输出和依赖关系。涉及外部系统时，应说明接口方向、交互对象和异常处理原则。

### R-OVERVIEW-EXAMPLE-003：关键非功能要求

应识别安全、性能、可用性、审计留痕等关键非功能要求，并说明其与业务目标或适用制度的对应关系。

## 审批结论与后续动作

审批意见应引用具体章节或附件。存在待补充项时，应明确责任人、完成期限及复核标准，避免仅记录笼统的“后续完善”。
