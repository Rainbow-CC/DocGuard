# 共享参考数据

> 所有审核方向共用的参考数据：问题等级定义、使用说明、制度依据与参考附录。审核时始终随所选规则文件一起加载。

## 问题等级定义

| 问题等级 | 定义 | 处理要求 | 示例 |
| --- | --- | --- | --- |
| 重大 | 审核要点不通过将直接影响系统安全、合规性或架构合理性，原则上报告不予通过，必须整改后重新提交。 | 必须整改后方可通过审核 | 使用抑制阶段软件版本、单节点数据库、RTO/RPO不满足等级要求、系统编码格式错误 |
| 一般 | 审核要点不通过表示报告存在缺陷或遗漏，需补充完善后方可通过审核。 | 限期补充完善后可通过 | 并发用户数与公式不匹配、缺少安全架构设计、第三方软件安全分析为空 |
| 优化 | 审核要点不通过为建议性改进项，不影响审核通过，但建议在后续阶段优化。 | 建议优化，不阻断审核流程 | 字体格式不完全符合模板、系统简称不够简洁、使用中性引导策略产品 |

## 并发用户数计算说明

| 项目 | 说明 |
| --- | --- |
| 计算公式 | 并发用户数 = 群体用户总数 × 并发率 |
| 并发率范围 | 5% - 20%（含边界值） |
| 校验规则 | 报告中每个用户群体的并发用户数 ÷ 群体用户总数 的比值应在5%-20%范围内 |
| 适用场景 | 适用于金融机构内部管理类、业务处理类系统的常规并发场景 |
| 异常处理 | 若并发率<5%，需在报告中说明低并发原因；若并发率>20%，需在报告中说明高并发业务场景依据 |
| 参考依据 | 技术可行性报告模板3.3节用户说明表格中的"群体用户总数"和"并发"字段 |

## 使用说明

| 序号 | 说明项 | 详细说明 |
| --- | --- | --- |
| 1 | 文档目的 | 本表用于技术可行性研究报告的自动化审核。每个审核要点包含明确的通过条件，可供技术文档审核智能体作为skill判断规则使用。 |
| 2 | 审核流程 | 1. 解析技术可行性报告文档内容；2. 按审核编号逐条执行通过条件检查；3. 记录不通过项及对应等级；4. 汇总生成审核报告。 |
| 3 | 通过条件格式 | 通过条件列使用可执行规则描述，包括：正则表达式匹配、数值比较、枚举值校验、字段非空检查、关键词匹配、目录/版本序列比对等。 |
| 4 | 问题等级 | 重大：必须整改后方可通过；一般：限期补充完善后可通过；优化：建议优化，不阻断审核。 |
| 5 | 制度依据 | 每条审核要点标注出处制度文号及对应条款号，便于追溯。制度更新时需同步更新对应审核要点。 |
| 6 | 参考附录 | 技术平台目录（软件/硬件）和软件版本序列作为参考附录sheet附后，后续版本更新时替换对应sheet数据即可。 |
| 7 | 系统编码与简称规范 | 系统编码格式（XYYYNN）和系统名称/简称规范性规则后续会根据公司新规范具体写入，当前版本已留出空位（AP-A07备注），待规范发布后更新。 |
| 8 | 信创系统判定 | 信创工程系统判定依据：公司信创工程系统清单。非信创系统也应优先选择信创产品，选择非信创产品需提供理由说明。 |
| 9 | 并发率范围 | 并发率5%-20%为金融机构常用区间，可根据具体业务场景调整。如系统有特殊高并发/低并发需求，报告中需提供业务依据。 |
| 10 | 更新维护 | 本规则表由信息科技部维护。制度更新、技术平台目录更新、版本序列更新时，需同步更新对应审核要点和参考附录。 |
